Co je Agent Evals

Agent Evals je evaluation framework pro AI coding agenty (Claude Code, Codex, OpenCode). Spustí Markdown testovací scénáře, automaticky vyhodnotí výsledky pomocí deterministických kontrol a LLM judgingu, a produkuje strukturované metriky.

Runner Actor

Spustí jeden scénář s jedním agentem. Parsuje markdown, inicializuje workspace, spouští agenta, vyhodnocuje checkpointy.

Production

Orchestrator Actor

Orchestruje více scénářů najednou. Plánováno pro Fázi 3.

Planned

Shared Library

Sdílené typy, parsery, agent adaptery, judge logika, metriky, OTel.

Execution Flow

Input (scenario + config) → Parse scenario → Init workspace → Run preset + init script → Detect plugins
For each test: → Spawn agent → Stream NDJSON events → Extract trajectory → Monitor (optional)
Judge checkpoints → Compute verdicts → Retry on fail? → Push to dataset → Flush OTel + logs

Podrobnosti execution flow:

  1. Parse scenario — parseScenario() extrahuje YAML frontmatter + test bloky
  2. Init workspace — izolovaný /tmp/eval-workspace-{UUID}
  3. Init preset — nainstaluje nástroje, zapíše MCP config, spustí custom script
  4. Plugin auto-detect — pokud init script umístil .claude-plugin/plugin.json, přidá --plugin-dir
  5. Agent run — child_process.spawn(), NDJSON stream parsing
  6. Trajectory — tool calls, soubory, příkazy, MCP tools, error recovery
  7. Monitor — volitelný follow-up agent call
  8. Judge — deterministické kontroly + LLM judge
  9. Retry — na fail: nový workspace, znovu init + agent + judge (max maxRetries)
  10. Output — Actor.pushData(AgentResult) per test, logs do KV store, OTel trace

Quick start (první run)

Vstupní pole Testing Scenario je prefilované funkčním příkladem (jedna otázka na Jupiter, checkpoint contains: Jupiter + LLM judge). Nejkratší end-to-end první spuštění:

  1. Vyber agenta. Default claude-code na claude-sonnet-4-6 stačí pro většinu scénářů. Alternativy: codex, opencode.
  2. Vlož credentials do pole Environment Variables (JSON object, secret, automaticky maskovaný v logech): 
    {"ANTHROPIC_API_KEY": "sk-ant-..."}

    Pro Claude subscription/OAuth viz poznámka na konci sekce Init Presets.

    {"OPENAI_API_KEY": "sk-..."}
    // klíče závisí na konfigurovaném model provideru
  3. Klikni Start. Aktivní defaulty: $1 budget cap (soft, jen claude-code), 10 max turns per test (jen claude-code), init preset none.
  4. Sleduj run živě. V detailu runu: Storage → Key-value store → LIVE-AGENT-LOG (NDJSON, streamuje se token-by-token jak agent generuje — text_delta / thinking_delta). LIVE-JUDGE-LOG streamuje LLM judge stejným způsobem.
  5. Po doběhnutí obsahuje Dataset jeden item per test s overallVerdict, per-check verdicts[], metrics, efficiency a trajectory. Plné event streamy v CONVERSATION-LOG / JUDGE-LOG, OpenTelemetry trace v OTEL-TRACE. Schema viz Output.

Pozn. Jediný povinný input je scenario; všechna ostatní pole mají rozumný default. maxBudgetUsd a maxTurns respektuje pouze claude-code (CLI Codex a OpenCode ekvivalentní flagy nemají — viz Agent registry).

Scénář je Markdown soubor s YAML frontmatter. Obsahuje jeden nebo více testů, každý s promptem a checkpointem.

Multi-test scénáře

Testy se oddělují --- (YAML document separator). Separator musí být na vlastním řádku a následovaný ## Test.

Checkpoint typy

Checkpoint sekce obsahuje N kontrol. Všechny musí projít pro overall pass.

Dva formáty zápisu

Prefixované řádky nahoře, plain text dole (= LLM judge):

contains: Jupiter
regex: \b(largest|biggest)\b
The answer should be scientifically accurate.

Pravidlo: prefix řádky se parsují dokud nenarazí na první non-prefix řádek → zbytek = LLM judge.

Pojmenované subsekce pro komplexnější kontroly:

### Checks
contains: Jupiter
warn-regex: gas giant

### Script
cat /tmp/demo.json | jq -e '.items == 3'

### Judge
The answer must be scientifically accurate.

### Judge (opus)
Deep analysis of code architecture.

### warn-Judge (haiku)
Optional: is error handling present?

Subsekce: Check/Checks, Script/Scripts, Judge/warn-Judge (case-insensitive). Více ### Judge bloků = více nezávislých LLM volání.

Deterministic checks

CheckSyntaxJak funguje
contains contains: text Case-insensitive substring match v agent outputu
regex regex: \d{4} Case-insensitive regex test nad agent outputem
json-schema json-schema: {"type":"object",...} Ajv validace. Auto-extrahuje JSON z code bloků v outputu.
script script: cmd nebo ### Script blok Bash script. Agent output na stdin. Exit 0 = pass. Stdout = evidence. Timeout 60s. Vidí workspace soubory.
jq jq: expression jq -e nad conversation events (JSON array). Exit 0 = pass. Timeout 30s.

LLM Judge

SyntaxModelSeveritySchema
Plain text (flat format)Sonnet (default)fail{verdict, reasoning, eval_critique?}
### JudgeSonnet (default)fail{verdict, reasoning, eval_critique?}
### Judge (opus)Opusfail{verdict, reasoning, eval_critique?}
### Judge (haiku)Haikufail{verdict, reasoning, eval_critique?}
### warn-JudgeSonnet (default)warning{verdict, reasoning, eval_critique?}
### warn-Judge (haiku)Haikuwarning{verdict, reasoning, eval_critique?}

Model aliases: haiku → claude-haiku-4-5-20251001, sonnet → claude-sonnet-4-6, opus → claude-opus-4-6. Nebo plné model ID.

Tři severity:

  • fail — default; fail verdict shodí overallVerdict.
  • warning — warn- prefix; fail verdict se mapuje na warning, neshodí overall.
  • eval — eval- prefix; hodnotí kvalitu eval frameworku, ne agent výstupu. Produkuje CheckVerdict s checkType: 'eval-review', vyloučen z computeOverall. Pro autora scénáře = "judge řekne, jestli mé checky vůbec měří správnou věc".

Retry: max 2 pokusy, exponential backoff (1s, 2s). Fallback: null → unclear.

Severity prefix

Jakýkoli check type lze prefixovat warn- → fail se změní na warning (neblokuje overall pass):

warn-contains: optional text
warn-regex: nice-to-have pattern
warn-jq: [.[] | ...] | length > 0

Overall verdict logika

Verdikty s checkType === 'eval-review' (z ### eval-Judge) jsou vyloučeny z agregace — hodnotí eval framework, ne agenta. Z ostatních verdiktů se vybere podle precedence:

if (any platform_failure) → "platform_failure"
if (any fail)             → "fail"
if (any warning)          → "warning"
if (any unclear)          → "unclear"
else                       → "pass"

platform_failure je 5. hodnota VerdictValue: runner ho nastavuje, když v tool_use_result eventech najde Apify memory-limit chybu — odlišuje "agent selhal" vs. "platforma zabila proces".

jq checkpoint — conversation events

jq checkpointy operují nad conversation events (JSON array), ne nad agent text outputem. To umožňuje validovat jaké nástroje agent použil:

# Agent použil Bash tool
jq: [.[] | select(.type=="assistant") | .message.content[]?
     | select(.type=="tool_use" and .name=="Bash")] | length > 0

# Agent NEPOUŽIL zakázané tools
jq: [.[] | select(.type=="assistant") | .message.content[]?
     | select(.type=="tool_use") | .name
     | select(test("^Web(Search|Fetch)$"))] | length == 0

# Agent spustil konkrétní příkaz
jq: [.[] | select(.type=="assistant") | .message.content[]?
     | select(.type=="tool_use" and .name=="Bash")
     | .input.command? // ""
     | select(test("apify (actors )?call"))] | length > 0

mcp_only POUZE MCP Exkluzivní MCP surface. Vyžaduje mcpConfigJson. PATH-shimuje apify/curl/wget, zamítá WebFetch/WebSearch a shell mentioning api.apify.com přes trajectory hard-reject. Agent-agnostic.

api_only POUZE REST API (curl / fetch) Exkluzivní REST surface. PATH-shimuje apify. MCP config se nezapisuje. Zamítá jakékoli apify-cli volání nebo MCP nástroj. WebFetch a curl jsou povolené — JSOU to REST surface.

How *_only exclusivity is enforced

Three independent layers, all evaluated for every test:

  1. PATH shim — runner writes no-op shim binaries to a per-run OS-tmpdir directory (outside the agent's writable cwd) and prepends that directory to the agent subprocess's PATH. Direct invocation of a shimmed tool returns exit 127.
  2. MCP config gating — for cli_only/api_only the runner does not pass --mcp-config, so no MCP servers are loaded regardless of mcpConfigJson content.
  3. Trajectory hard-reject — after the agent finishes, the runner inspects the normalized trajectory (commandsExecuted, uniqueToolsUsed, mcpToolsUsed) against preset-specific rules and appends preset-trajectory verdicts. This is the agent-agnostic layer — it works for claude-code, codex, and opencode because the trajectory shape is normalized across agents. It's also the only layer that catches in-agent tools like WebFetch/WebSearch which can't be PATH-shimmed.

MCP Config JSON

Runner zapíše mcpConfigJson as-is do .eval-config/mcp-config.json — sám neprovádí interpolaci placeholderů. Agent (Claude Code CLI) pak konfiguraci načítá; zda ${APIFY_TOKEN} uvnitř env blocku resolvuje záleží na MCP runtime daného agenta. Hodnoty envVariables jsou zároveň předány agentově subprocessu, takže MCP servery spuštěné přes npx tyto proměnné zdědí v process.env.

{
  "mcpServers": {
    "apify": {
      "type": "http",
      "url": "https://mcp.apify.com",
      "headers": { "Authorization": "Bearer ${APIFY_TOKEN}" }
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}

Pokud init script (nebo custom bash) umístí .claude-plugin/plugin.json do workspace root, runner automaticky přidá --plugin-dir <workspace>. Nemusíte specifikovat nic dalšího.

Judge system

Pipeline

parseCheckpointSection() → deterministic checks → LLM judge calls → computeOverall()

parseCheckpointSection(checkpoint) → ParsedCheckpoint

interface ParsedCheckpoint {
    checks: CheckpointSpec[];  // deterministic checks
    judges: JudgeSpec[];        // LLM judge prompts
}

interface CheckpointSpec {
    type: CheckType;
    value: string;
    severity: 'fail' | 'warning';
}

interface JudgeSpec {
    prompt: string;
    severity: 'fail' | 'warning' | 'eval';  // 'eval' = ### eval-Judge (meta-eval, excluded from overall)
    model?: string;  // resolved from alias (haiku/sonnet/opus) or full model ID
}

judgeAllChecks(agentOutput, checkpoint, options?)

  1. Detekuje platform failures (memory limit exceeded)
  2. Spustí deterministické kontroly (contains, regex, json-schema, script, jq)
  3. Zapíše eval-checkpoint.json a eval-check-results.json do workspace
  4. Pro každý judge: enriched output = agent text + workspace files + conversation log → judgeLlm()
  5. Vrátí { verdicts, overallVerdict }

LLM Judge backend (agents/claude.ts)

judgeLlm() spouští Claude CLI jako subprocess s plným toolsetem (Read, Bash, Glob, …) — není to text classifier:

claude -p "{prompt}" \
  --output-format stream-json \
  --verbose \
  --include-partial-messages \
  --json-schema '{...verdict schema...}' \
  --model claude-sonnet-4-6 \
  --dangerously-skip-permissions \
  --no-session-persistence

Dvě schémata podle severity:

  • fail/warning Judge → {verdict: "pass"|"fail"|"unclear", reasoning: string, eval_critique?: string}
  • eval Judge (### eval-Judge) → {eval_gap_severity: "critical"|"noncritical"|"ok", reasoning: string} → produkuje CheckVerdict s checkType: 'eval-review', vyloučen z computeOverall.

Timeout: 5 min soft budget (JUDGE_TIMEOUT_MS), žádný max-turns limit. Retry: max 2 pokusy s exponential backoff (1s, 2s). Fallback: null → verdict unclear.
